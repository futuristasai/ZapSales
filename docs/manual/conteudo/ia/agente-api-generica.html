Para que serve

Uma API é a porta que um sistema abre para outros sistemas. A sua loja virtual, o seu ERP e o seu CRM quase sempre têm uma. Com ela o agente consulta ou faz algo lá durante a conversa: vê onde está um pedido, confere o estoque, registra um atendimento.

A diferença para as outras duas abas da mesma tela:

AbaQuando usar
APIs (esta página)O outro sistema já tem uma API pronta, com documentação. O ZapSales chama essa API do jeito que ela espera.
WebhooksVocê tem um intermediário (Make, n8n, um programa seu) feito para receber o aviso do ZapSales.
Servidores MCPO outro sistema oferece um servidor MCP, com um “cardápio” de ferramentas pronto para IA.
Você vai precisar da documentação da API.

Quem cadastra precisa saber o endereço, a operação e a chave de acesso que o outro sistema fornece. Se você não tem esses dados, peça ao suporte do outro sistema “a documentação da API e uma chave de acesso”.

O que esta versão não atende.
  • Sistemas que exigem um login que se renova sozinho (OAuth), como Mercado Livre e Bling: aqui a chave é um valor fixo que você cola.
  • Copiar dados de um sistema para o outro (importar contatos, catálogo). A API é usada durante a conversa.
  • Receber avisos do outro sistema (por exemplo, “entrou um pedido novo”).

Ligar o recurso (uma vez)

As APIs vêm desligadas em toda organização, e o sistema funciona normalmente sem elas. Clique em Agente na faixa à esquerda, escolha Conectar outros sistemas (a tela se chama “Ferramentas externas”) e clique na aba APIs.

  1. No cartão APIs de outros sistemas (selo Desligado), leia e marque o aceite: “Entendo que, ao ligar, o agente pode enviar aos sistemas que eu cadastrar os dados que ele preencher ao usar uma API, e que o que eles responderem é tratado como informação, nunca como ordem.”
  2. Clique em Ligar as APIs. A tela confirma “APIs ligadas.”.

Se você desligar depois (Desligar as APIs, com confirmação), nada é apagado: as APIs, as chaves e as opções de segurança ficam guardadas. Nenhum agente usa mais nenhuma API, e pedidos que esperam aprovação não são executados até você ligar de novo.

Segurança das APIs

Ao ligar, a segurança nasce na posição mais fechada. No alto da aba, o cartão Segurança das APIs mostra um resumo: “Todas as opções estão na posição recomendada.” ou quantas — e quais — estão fora dela.

Nível de segurança

É uma escolha só, para você não precisar ajustar item por item:

NívelO que muda
Mais seguro (recomendado)O agente só consulta, e só administrador cadastra e aprova.
EquilibradoO agente também pode alterar dados, mas toda alteração espera uma pessoa aprovar. Gerentes podem aprovar.
PersonalizadoVocê ajusta opção por opção.

As opções, uma a uma

Clique em Ver e ajustar as opções uma a uma. Cada opção mostra, na própria tela, o que faz, um exemplo, a recomendação e o risco de sair dela.

Quando você muda uma opção para uma posição menos segura, a tela mostra o risco e a recomendação antes de salvar. O botão em destaque é Manter como está (recomendado); para seguir, clique em Mudar mesmo assim. A opção fica com o selo Fora do recomendado enquanto durar, e a mudança fica registrada com o seu nome. Voltar à posição recomendada é direto.

As opções valem na hora em que o agente vai usar a API, e não só no cadastro. Se você ligar “Somente consulta” ou limitar os endereços depois, uma API cadastrada antes deixa de ser usada no mesmo instante, e a lista diz por quê (“O agente não usa esta API agora.”).

Cadastrar uma API

Clique em Nova API. O formulário tem quatro partes.

1. O que esta API faz para o agente

  1. Nome. Por exemplo Consultar pedido na loja.
  2. Quando o agente deve usar. Escreva como instrução para uma pessoa: “Quando o cliente perguntar onde está o pedido dele.” É assim que o agente decide se chama a API.

2. Como chamar a API

  1. Operação. GET consulta; POST, PUT e PATCH enviam dados; DELETE apaga.
  2. Endereço. Começa com https://. Para usar um campo no endereço, escreva o nome dele entre chaves duplas, depois do nome do site: https://api.loja.example.com/pedidos/{{numero}}. O agente preenche o número do pedido, nunca para onde a chamada vai.
  3. Como a API confere quem está chamando. Chave no formato Bearer (o mais comum), chave em um cabeçalho com outro nome (por exemplo X-API-Key), usuário e senha ou não pede chave.
  4. Chave de acesso. A “senha” que o outro sistema deu. Fica guardada cifrada e nunca é mostrada de novo (só “chave …xxxx”). Para trocar, abra Editar e escreva a nova; deixar em branco mantém a que está guardada.
  5. O que vai no corpo da chamada (só em POST, PUT e PATCH). Os campos, do jeito que o agente preencher, ou um modelo que eu escrevo, quando a API exige um formato próprio.
  6. Cabeçalhos fixos (avançado). Só se a documentação pedir, como a versão da API. A chave de acesso não vai aqui.
Crie uma chave só para isto.

Se o outro sistema permitir, crie uma chave de acesso exclusiva para o agente, com o mínimo de permissões — por exemplo, só leitura de pedidos. Se algo der errado, você cancela essa chave sem afetar o resto.

3. Dados que o agente preenche

Cada campo é um espaço que o agente completa antes de chamar: número do pedido, nome do produto. Diga o nome do campo, o tipo (texto, número, número inteiro, sim ou não) e o que o agente coloca nele.

Em cada campo você pode limitar os valores permitidos: uma lista de opções para texto (pago, cancelado) ou um mínimo e um máximo para número (quantidade de 1 a 10). O agente não consegue chamar com um valor fora do permitido.

Se alguma dessas opções ficar fora do recomendado, ao salvar a tela lista os riscos. O botão em destaque é Voltar e ajustar (recomendado); para seguir, clique em Salvar mesmo assim. A API fica com o selo Fora do recomendado na lista.

Dados do contato: o sistema preenche, o agente não escolhe

Imagine que qualquer pessoa pudesse digitar “qual o status do pedido 4512?” e receber os dados do pedido de um estranho. Para evitar isso, marque Telefone em “Dados do contato que esta API recebe” e use {{contato_telefone}} no endereço ou no corpo. O sistema preenche com o telefone de quem está na conversa — o agente não consegue trocá-lo pelo de outra pessoa.

Um dado só pode ser marcado se um administrador o liberou em Segurança das APIs › Dados do contato que podem sair. Pela LGPD, o envio de dados pessoais a outro sistema precisa estar previsto na sua política de privacidade.

Testar de verdade

Na lista, clique em Testar de verdade. Preencha os campos com dados de exemplo e clique em Chamar agora. A tela mostra o que o agente vai ler e o que foi enviado (sem a chave de acesso).

Testar uma API que altera dados altera de verdade.

O teste faz a chamada real ao outro sistema, com os dados de exemplo, sem pedir aprovação — quem clica é você. Use dados que possam ser apagados depois.

Ligar a API em um agente

Cadastrar não basta: a API só é usada pelos agentes em que você a marcar. Abra o agente, vá até Ferramentas externas e marque a API (ela aparece com o selo API). Publique a nova versão do agente.

Para parar de uma vez, em todos os agentes, use o interruptor Ativa / Pausada na lista de APIs.
