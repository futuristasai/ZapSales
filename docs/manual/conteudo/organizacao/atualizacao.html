Para que serve

Mostra a versão instalada no servidor e, quando há uma nova, o que muda nela — e deixa o dono mandar o servidor atualizar. É uma tela do servidor, não da empresa: “Administrador” da empresa não a vê (recebe “página não encontrada”), e ela não tem item no menu nem na página de área Configurações. A porta é o rodapé do painel Todo dia, ao lado da faixa, junto do link Manual: mostra “versão X.Y.Z” e, só para o dono, quando há versão nova, vira o link “Nova versão · X.Y.Z” com um ponto pulsando.

  • Painel recolhido (setinha «): a versão não cabe na faixa e some, mas o aviso de versão nova continua à vista, no pé da faixa, abaixo de Você, como um ponto pulsando com uma seta.
  • Celular: o mesmo rodapé (Manual e a versão ou o aviso) fica no fim de cada folha da barra de baixo — Todo dia, Configurar e Resultados.
  1. Título do estado. Diz em que situação a tela está (veja a tabela abaixo).
  2. O comando de atualização. É o mesmo da instalação; rode no servidor.
  3. Copiar. Copia o comando para colar no terminal do servidor.
  4. Versão instalada. O número da versão, ou “ainda não informada pelo servidor”.

A captura mostra o estado em que o sistema não consegue falar com o servidor onde está instalado: “Quem tem acesso ao servidor pode entrar na pasta onde o sistema foi instalado e rodar este comando — se for a primeira vez, rode duas vezes: a primeira baixa o programa novo e a segunda liga o botão desta tela.” O comando é curl -fsSL https://zapinstalador.futuristas.app/obter.sh | sudo bash, com o botão Copiar. Abaixo do comando, a linha “Versão instalada:” mostra o número, ou “ainda não informada pelo servidor” quando o servidor nunca respondeu desde a instalação.

O que o comando faz.

É o mesmo comando da instalação: ele traz a versão nova, reinstala por cima e faz um backup antes de mexer no banco, sem perguntar de novo o que já foi respondido. Rode como administrador (sudo) no servidor, de qualquer pasta. Veja Instalar o ZapSales numa VPS › Atualizar. Versões antigas da tela mandavam rodar bash kit/update.sh, um arquivo que não existe no kit (issue #173, corrigida): se o seu servidor ainda mostrar esse comando, use o de cima.

Os estados da tela

A descrição padrão é “A versão instalada no servidor e, quando houver uma nova, o que muda nela.” Cada estado tem título próprio:

TítuloO que significa e o que fazer
Carregando…Lendo a versão.
Você está na versão X“É a mais recente. Não há nada a fazer.”
Versão X disponívelMostra a caixa “⚠️ Requer atenção” (“Da versão X:” com avisos de ação manual), o aviso de histórico incompleto, a seção “O que muda” (notas da versão-alvo abertas; as intermediárias recolhidas) e o botão Atualizar agora (“Iniciando…”) com a nota “O sistema sai do ar por cerca de 2 minutos e volta sozinho. Faço uma cópia de segurança dos seus dados antes.” Em instalação de desenvolvimento aparece um aviso amarelo de que a atualização leva à versão publicada.
Pedido enviado — esperando o servidor pegarO servidor confere se há algo a fazer “de poucos em poucos minutos”, então a atualização pode levar até cerca de cinco minutos para começar; ficar parada nesse tempo é normal. “Pode fechar esta página: o pedido já está registrado e não se perde.”
Atualizando para a versão XQuatro passos com ✓/○: “Guardando uma cópia de segurança dos seus dados”, “Baixando a versão nova”, “Atualizando o banco de dados”, “Reiniciando o sistema”. Depois, “Reiniciando…”: “O sistema está voltando. Esta página se atualiza sozinha em alguns instantes.”
A atualização para a versão X terminouQuando o servidor ainda não confirmou em que versão voltou ao ar, mostra a última confirmada.
A atualização para a versão X não deu certoDois desfechos, com o mesmo título. Num deles o sistema voltou sozinho para a versão anterior (“Voltei o sistema para a versão Y … os seus dados estão intactos”); no outro, “não consegui voltar sozinho”: o sistema pode estar numa versão com defeito ou fora do ar, e a cópia de segurança feita antes continua guardada no servidor. Nos dois a tela mostra o comando para rodar no servidor que deixa tudo na versão que funcionava (curl -fsSL https://zapinstalador.futuristas.app/obter.sh | sudo ZAPSALES_REF=vX.Y.Z bash) e “Detalhes técnicos (útil se for pedir ajuda)”. Nesses estados não há botão Atualizar agora.
Não sei dizer como terminouO servidor perdeu contato antes do fim. “Confira se o sistema está funcionando normalmente — se estiver, provavelmente deu certo.” Mostra o comando de atualizar (o mesmo de cima) para conferir pelo servidor e os “Detalhes técnicos”.
Atualização automática indisponívelVeja acima: rode o comando no servidor.
“Não consegui checar se há versão nova”, “Ainda não há nenhuma versão publicada”, “Você está à frente da versão publicada”Casos de borda; a tela explica cada um.
Atualizar tira o sistema do ar para todos.

O pedido é anotado e o agente do servidor (que confere a cada ~5 minutos) faz a cópia de segurança, baixa a versão, atualiza o banco e reinicia: o sistema fica fora do ar por cerca de 2 minutos para TODAS as empresas e usuários da instalação. Registra o pedido (system.update_requested) e o fim (system.update_finished) em Quem mexeu em quê (a Auditoria). Esta tela não foi acionada nas capturas; atualização é um ato de operação do servidor, não do uso diário. Para a regra de versões e o que cada versão traz, veja o histórico de mudanças (changelog) do produto.
